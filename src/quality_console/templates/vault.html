Vault live

Which credentials the services hold now, for how long, and the one that never expires.

No service talks to Vault. A Vault Agent beside them logs in with its AppRole, asks Vault for each service's credentials and writes them into a file the service reads at each connection. A short-lived credential is a MySQL or RabbitMQ user Vault creates for one service: it lives 2 minutes, the agent renews it up to 6 minutes, then asks for a new one and rewrites the file; Vault drops the old user when its lease ends. A leak is worth minutes. The long-lived one is the Bank Partner's key: the bank issued it once, Vault only keeps it, the bank decides when it changes.

The page reads Vault with the console's own token: it lists leases and reads metadata, never a value. The page refreshes every 10 seconds; the bars run down in between. The full Vault UI is on localhost:8200 (token root, dev mode).
